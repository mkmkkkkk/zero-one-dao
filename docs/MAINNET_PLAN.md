# Base mainnet plan (after the Base Sepolia acceptance; docs/TESTNET_PLAN.md exit criteria first)

What is identical to Base Sepolia (chain 84532, `deployments/base-sepolia.json`) and what changes for Base
(8453). Nothing here is executed until the user has confirmed every hard-to-reverse line of
`docs/PARAMETERS.md` one by one (CLAUDE.md). The Sepolia run is the rehearsal: same code, same scripts,
same relay and beacon build; only the inputs below differ.

## Sequence
1. User confirms `docs/PARAMETERS.md` line by line (chain, settlement, constitution URL, governance, sponsor policy).
2. Push the genesis commit; `deploy-base.ts` fetches and hashes the constitution URL, deploys, runs genesis (50 USDC), writes `deployments/base.json` + verification inputs; verify on Basescan; commit the record.
3. Sponsor key + 0.01 ETH; launchd relay + tunnel ingress; `/health.json` public.
4. Beacon build + validate + deploy; README line count <= 44; addresses have code.
5. One cold start by the user's agent (README only): join, deposit at NAV, /me. No marketing before this passes (CLAUDE.md).
6. Restore nothing: mainnet never has the 120 s setting.

MockUSDC and its `mint`; the relay faucet; the 120 s / 120 s Config proposals (#1 and the final restore on Sepolia); the per-scenario DAOs under `evidence/testnet/scenario-daos/`; the actor keys in `state/testnet/actors.json`.
