# Zero One DAO — hard-to-reverse parameters (confirm each line before mainnet)

Every line is one parameter, its current value in `src/zeroOne.ts` / the contracts, and why. Lines
marked **IMMUTABLE** cannot be changed after deployment by anyone, including a unanimous vote; the
only remedy is a new deployment. Lines marked **BY PROPOSAL** are the initial state and can be
changed later by an ordinary proposal (DESIGN.md §3/§0). Lines marked **DECIDE** have no value yet.

## Chain and identities
- chain = Base (8453). **DECIDE** — Baal (Zero One fork, see below), Safe, factories and MultiSendCallOnly singletons are re-deployed by us, so no dependency on DAOhaus' canonical addresses.
- founder = the deployer EOA. **NOT A CONTRACT PARAMETER** — no contract stores or privileges a founder address; the founder is an ordinary member whose only shares come from the 50 USDC genesis deposit and from work paid by vote (DESIGN.md §6). The key matters only as the holder of those shares.
- settlement asset (`NavShareToken.settlementToken`) = USDC on Base, `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` (6 decimals; `BASE_USDC` in `src/zeroOne.ts`, documented only, nothing deployed). **IMMUTABLE** — defines NAV forever: deposits and exits are priced in it (task rewards are not, see Work). Mirror uses `TestToken` "USDC-mock" (6 decimals, fixed supply, no admin). USDC is upgradeable and has a blacklist (Circle); a blacklisted Safe could not pay exits — accepted as the user's choice (DESIGN.md §6). Must not be fee-on-transfer or rebasing (DepositShaman reverts on inexact transfers; ragequit assumes balanceOf accounting).
- salt = 1; Safe/Baal proxy create2 nonces = keccak256(abi.encode(deployer, salt, 0 | 1)) (`proxySaltNonce` in `src/zeroOne.ts`; phase 5 ruling 8, OPS-04). **IMMUTABLE** — only affects addresses. Two deployers with the same salt never predict the same proxy; the vendored factories still let a front-runner create or initialize a proxy at the predicted address first, after which the deployment aborts before any value moves (griefing only; retry with a new salt).

## Constitution (Constitution contract, DESIGN.md §10)
- `Constitution.textHash` = keccak256 of the exact bytes of `docs/CONSTITUTION.md` = `0xebc7c39cf14fdc0ac2c028cdba5960ecc4560a314e613b93b4585b62826f2d9a` (computed by `constitutionHash()` in `src/zeroOne.ts` at deploy time and asserted equal on-chain; every scenario boot re-asserts it). **IMMUTABLE** — no setter, no owner, no amendment path (constitution Art. VII). Changing one byte of the text changes the hash; the text file is therefore frozen with the deployment. A new constitution means a new deployment.
- `Constitution.textUrl` = `"docs/CONSTITUTION.md"` (`CONSTITUTION_TEXT_URL` in `src/zeroOne.ts`; mirror value, a repo-relative pointer). **DECIDE** — the mainnet value should be a stable public URL of the exact bytes (the hash, not the URL, is the authority). Written once in the constructor; Solidity strings cannot be `immutable`, and no function writes storage afterwards.

## Treasury and governance module
- Safe owners = [Baal], threshold 1, enabled modules = [Baal] only. **IMMUTABLE in practice** — no EOA can sign for the Safe; Baal executes passed proposals through the module path. A proposal could in theory add owners/modules (it is "anything"); by design that is a vote, not a code rule.
- Baal implementation = the Zero One fork of @daohaus/baal-contracts 1.2.18 `Baal.sol` (`contracts/vendor/Baal.sol`, compiled with solc 0.8.36 like every other contract; every changed line is marked `ZERO ONE:`), minimal proxy via ModuleProxyFactory. **IMMUTABLE** — no upgrade path. The whole diff against the package source (phase 5 rulings 1 and 2):
  1. `submitProposal`: `require(baalGas <= 8000000)` instead of 20,000,000 — the relay's sponsor maximum, under Base's EIP-7825 per-transaction cap (16,777,216), so no proposal can ever demand more processing gas than one transaction carries (GOV-05).
  2. `submitProposal` (self-sponsored) and `sponsorProposal`: `NavShareToken.registerProposal(id)` records the epoch at which voting starts.
  3. `processProposal`: the high-water-mark retention check is replaced by `NavShareToken.exitedSince(id)`: the proposal fails when `exited × 100 > (100 − minRetentionPercent) × supplyAtStart`, where `exited` = shares that existed at votingStarts and were burned since and `supplyAtStart` = share supply at votingStarts (loot is never minted and plays no part). Deposits move neither side; a deposit made after votingStarts and exited again (flash or not) never counts (GOV-03, GOV-04). Boundary: exactly 34% leaving keeps the proposal alive.
  4. One explicit `import ContextUpgradeable` (resolved transitively by the package's own build; no semantic change).
  `submitVote` still records `maxTotalSharesAndLootAtVote`; the value is unused.
- multisend library = `MultiSendCallOnly` (`contracts/vendor/MultiSendCallOnly.sol`, verbatim safe-contracts 1.3.0), used for the Safe setup, Baal's `multisendLibrary` and every proposalData builder (same `multiSend(bytes)` selector). **IMMUTABLE** — a proposal's inner transaction with operation 1 (delegatecall as the Safe) reverts; the Safe can only *call* (phase 5 ruling 6, ECO-06 / A5-11).
- baalGas of our own submit paths (phase 5 ruling 1): `src/proposals.ts` `baalGasFor` = the voted action simulated as Baal executes it (Safe `execTransactionFromModuleReturnData` from Baal, binary search over the eth_call gas limit because the Safe reports an inner failure instead of reverting) × 1.5, capped at 8,000,000, fallback 2,000,000 when the action fails at every limit; `ZeroOneIntentAccount` op 0 = the intent's `proposalId` field when non-zero (the relay's simulation, ≤ 8,000,000) else `DEFAULT_BAAL_GAS` = 2,000,000; `WorkManager.submitTask` = `ACTIVATION_BAAL_GAS` = 500,000 (the fixed `activateTask` action needs < 100k). A direct Baal submitter who passes 0 accepts the low-gas kill risk on its own proposal (GOV-01). **PROCEDURAL / IMMUTABLE constants**.
- adminLock = true. **IMMUTABLE** — no admin shaman can ever be added; share/loot pause does not exist anyway (tokens revert on pause), so this closes nothing the design wants open.
- managerLock = false. **BY PROPOSAL (one-way)** — a passed proposal can add another minting shaman or lock managers forever. Left open on purpose: a new WorkManager/DepositShaman version must be installable by vote; members stop a bad one by NO or exit (DESIGN.md §0). Locking it would be a rule in code.
- governorLock = false. **BY PROPOSAL (one-way)** — same reasoning; no governor shaman is installed at genesis, so governance config changes only through proposals.
- trustedForwarder = 0x0. **BY PROPOSAL** — sponsored gas uses the EIP-7702 adapter, not EIP-2771.
- manager shamans at genesis = [DepositShaman, WorkManager], permission 2 each. **BY PROPOSAL** — the only two mint paths (DESIGN.md §2 a/b); Baal.mintShares is also callable by the Safe, i.e. by a passed proposal. Every scenario boot enumerates ShamanSet logs and asserts exactly this set; scenario F additionally enumerates every mint ever made.

## Initial governance config (all BY PROPOSAL via Baal.setGovernanceConfig; scenario D proves it)
- votingPeriod = 21600 s (6 h) — agents poll at least hourly, ≥ 6 chances to see a proposal.
- gracePeriod = 21600 s (6 h) — exit window after the vote closes, before execution.
- proposalOffering = 0 — no ETH tribute to submit.
- quorumPercent = 0 — silence is consent; abuse is stopped by exit, not turnout.
- sponsorThreshold = 1 share (1e18 wei-shares) — anti-spam only. Baal will not accept a threshold above totalShares, and at genesis totalShares = 0: the founder can sponsor as soon as the genesis deposit (50 USDC → 50e18 shares) is made.
- minRetentionPercent = 66 — a proposal fails automatically if > 34% of the shares that existed at votingStarts exit during vote + grace (fork rule above; Base Sepolia corner case: exactly 34% leaving keeps the proposal alive, 37.7% defeats it). A YES voter who exits is such an exit (GOV-02, accepted by principle): above 34% of supply it defeats the proposal by retention; below it only beats members who never voted NO in 6 h (DESIGN §4 sleepers).
- Baal treats a votingPeriod or gracePeriod of 0 in `setGovernanceConfig` as "unchanged"; the Config template's `start()` then reverts `NotApplied` and the whole action fails (`actionFailed`, nothing applied). The minimum settable period is therefore 1 s, and a 1 s / 1 s DAO is terminal on a 2 s-block chain: no block can carry a vote and `0 yes > 0 no` is false, so nothing passes again, a repair included. Allowed by design; documented consequence (Base Sepolia corner cases `absurd-*`).

## Share token (NavShareToken)
- name = "Zero One Shares", symbol = "ZERO1", decimals = 18. **IMMUTABLE**.
- non-transferable: transfer / approve / transferFrom always revert. **IMMUTABLE** — shares are weight, not an asset; the only way out is ragequit at NAV. Baal accepts `ragequit(0, 0)` as a no-op (nothing burned, nothing paid) and requires the token list in ascending address order (`!order`); an asset other than the settlement is paid only when the member names it (no guildTokens registry in Baal v3).
- votes = balance, self-delegated, timestamp checkpoints; no delegation. **IMMUTABLE**.
- mint / burn callable only by Baal. **IMMUTABLE**.
- no pause, no lock, no cliff, no unvested gate: every share is exitable the moment it exists. **IMMUTABLE** (the design's "owned means exitable").
- deposit pricing lives in DepositShaman (below); `navSharesFor` / `navValueForShares` on the token are Safe-only informational views. **IMMUTABLE**. The first depositor (the founder's genesis deposit) holds 100% of what exists. There is no zero-supply trap (phase 5 ruling 8, OPS-03): while totalSupply = 0 one USDC mints 1e18 shares regardless of what the Safe holds, so settlement that lands in the Safe before genesis (or after everyone exited) is a gift to the next depositor; `genesisDeposit` refuses only supply > 0.
- retention accounting (phase 5 ruling 2): shares are held in per-account mint lots stamped with the registration epoch (number of sponsored proposals so far); burns consume the newest lots first and credit their epoch in a Fenwick tree (`MAX_EPOCHS` = 2^24 registrations, i.e. sponsored proposals, over the DAO's life; beyond it sponsorship reverts `EpochsExhausted` — 16.7 M sponsorships at ≥ 200k gas each is not an economic path). `registerProposal` is Baal-only; `exitedSince(id)` is the view the fork reads. Cost: one O(24) storage update per lot a burn consumes; an account's lots merge while no proposal is sponsored between its deposits. **IMMUTABLE**.
- LootToken exists with zero supply, mint/burn only by Baal, transferable. **IMMUTABLE** — Baal requires a loot token; nothing mints it unless a proposal installs a shaman that does.

## Deposits (DepositShaman)
- open to any address, no membership check. **IMMUTABLE** — "phase 1 agents only" is a constitution clause enforced by votes (DESIGN.md §2). Scenario C's depositor D is a non-member at deposit time.
- shares = amount × (totalShares + liability) / `ledger.depositTreasury()` at deposit time; depositTreasury = Safe USDC + USDC held by open instances; liability = `WorkManager.activeRewardShares()` = Σ rewardShares of Active, unexpired tasks (shares already voted away, not yet minted; phase 5 ruling 4c, W-1). totalShares = 0 (genesis or after every share exited) or treasury = 0: 1 USDC → 1e18 shares. Exact-amount transfer required. **IMMUTABLE**. Ready-but-unexecuted Payments are not a liability in code; they are visible in the relay's /me as treasury effect (accepted, documented).
- TreasuryLedger: immutable Safe, settlement and factory; only instances in the factory deployment record can open/close. Voted starts enter the active set; closed instances leave. Strategy assets register once and remain registered forever (informational). **IMMUTABLE**.
- Settlement refusal (phase 5 ruling 4a, NAV-07): `TreasuryNotSettled` while any OPEN instance holds its registered asset. Safe balances are never consulted: 1 wei of a registered asset on the Safe changes nothing (it is shared by exit; a non-USDC gift to the Safe is likewise shared by exit only). No asset valuation, configurable switch or privileged bypass. What pauses deposits is therefore only capital the members voted out: a running Strategy holding its asset (its whole DCA life), or a stopped Strategy until a later `unwind()` / `migrate()` vote; 1 wei sent by a stranger to such an open instance keeps it open until that vote (documented residual; the instance was closed for deposits anyway). **IMMUTABLE**.
- Ragequit pays pro-rata of the Safe only; USDC deployed on open instances is counted for entry but forfeited to stayers on exit. Exit price is at most deposit price while settled. **IMMUTABLE**.
- deposits go straight to the Safe; no minimum, no maximum, no cap. **IMMUTABLE** by design (§0).

## Work (WorkManager)
- verifier ≠ proposer, proposer = msg.sender of submitTask, enforced at the only entry point. **IMMUTABLE** (DESIGN.md §5, constitution clause 5).
- verifiers cannot claim their own task. **IMMUTABLE**.
- reward is a number of shares (`rewardShares`, 18 dec) fixed at `submitTask`, voted as part of the task proposal, and minted exactly on the final confirmation; no NAV or settlement conversion, so tasks work at zero treasury. **IMMUTABLE** (DESIGN.md §5).
- single delivery per round, re-delivery resets confirmations; activate / cancel only by the Safe (i.e. by a passed proposal). **IMMUTABLE**.
- task expiration = the `expiration` passed to `submitTask` (also the Baal proposal expiration; 0 = none): `confirm()` reverts `TaskExpired` after it, `activateTask` reverts after it (the activation fails atomically), anyone may `expireTask()` an Active task past it, and `activeRewardShares()` stops counting it at once (phase 5 ruling 4c). A task with expiration 0 is a liability until confirmed or cancelled by vote — the proposer's choice, visible in the vote. **IMMUTABLE**.
- `CLAIM_TIMEOUT` = 7 days: a claim that has delivered nothing for that long lapses and the next `claim()` takes the task over (phase 5 ruling 10, W-2). A claim that delivered does not lapse; a garbage delivery is still ended only by a cancel vote. **IMMUTABLE constant**.
- no referral grants in phase 1 (AowReferralRewards is not in the reuse list); adding them later means a new shaman by proposal.

## Proposal-contract templates (DESIGN.md §7; docs/TEMPLATES.md; scenarios D, G-J)
- Per instance, set in the constructor and never changed: `safe` (owner of every instance), `settlement` (USDC), `operator` (= the proposer, the `member` argument of the factory deployment). **IMMUTABLE per instance** — a proposal contract belongs to the Safe from birth; the proposer can never reclaim it.
- TemplateFactory + four deployers (Payment, Strategy, Project, Config): `safe`, `settlement`, `baal` and the four deployer addresses are immutable; instance address = CREATE2(deployer, salt, keccak256(creationCode ‖ abi.encode(safe, settlement, member, ledger, params))). `deploy` is permissionless and idempotent (an existing instance is returned); who pays gas changes nothing about the code or the operator. **IMMUTABLE** — the intent account's op 0 is bound to this factory; a new template set means a new factory and a new adapter (both by proposal-free redeploy + members re-joining; decision.md phase 2b ruling 2).
- `start / topUp / amend / stop / migrate` are `onlySafe` in `ProposalBase`. **IMMUTABLE** — the only caller is a passed proposal executed by Baal through the Safe module path (constitution Art. IV.3). Scenarios G, H, I, J assert the proposer's direct calls revert `OnlySafe`.
- Strategy: `venue` and `asset` immutable per instance; the rule (`maxPerRun`, `minInterval`, `deadline`, `takeProfitBps`, `stopLossBps`, `slippageBps`) and `budget` change only by `amend` / `topUp` (Safe). `run()` is permissionless. `stop()` returns the raw settlement to the Safe without calling the venue and keeps the asset inside the (Stopped) instance, which stays open in the ledger until a later vote either `migrate()`s the raw holdings (no venue call; scenario J drains the venue before migrating) or `unwind()`s them on the venue under the rule's `slippageBps` (phase 5 ruling 4b; both onlySafe; `stop()` + `unwind()` can share one multicall). A stopped instance holding no asset closes at once. **IMMUTABLE per instance**.
- Project: verifiers ≠ operator, distinct, non-zero, `1 <= threshold <= n` enforced in the constructor and in `amend` (the only two entries). **IMMUTABLE**. Tranches are released to the operator only; `end()` after the deadline and the last release return everything else to the Safe. Once the deadline has come, `release()` and `confirm()` revert `DeadlinePassed` and `start()` refuses (the funding action fails atomically): the destination of a due-but-unreleased tranche is the Safe, never the winner of a transaction race (phase 5 ruling 10, T-7). A Date tranche dated at or after the deadline can never be paid.
- Config: applies nothing itself; the Safe calls `Baal.setGovernanceConfig` in the same multicall and `start()` verifies the six values (`NotApplied` reverts the whole action). No governor shaman is installed (governorLock false, see above).
- MockDex: mirror only, constant price settable by anyone; never deployed to mainnet. Strategy venues on mainnet are named in the proposal parameters and must implement `IStrategyVenue`.
- Execution gas: `Baal.processProposal` marks `actionFailed` instead of reverting when the voted multicall runs out of gas, and `eth_estimateGas` can therefore return a limit that is too small for the action. The mirror sends `processProposal` with an explicit 5,000,000 gas limit (`PROCESS_GAS` in `scenarios/lib.ts`); the relay's `execute` verb must do the same. **PROCEDURAL**.
- Testnet settlement: `MockUSDC` (6 decimals, `mint` restricted to the deployer) on Base Sepolia only; the relay faucet draws from the sponsor's minted balance. Never on mainnet (docs/MAINNET_PLAN.md).

## Phase 4 venue pricing
- UniswapV3Venue TWAP window = 30 minutes (1,800 seconds), from pool.observe tick accumulation, settlement per assetUnit. Constructor refuses a pool whose observation history cannot serve the window. **IMMUTABLE**.
- Both buy and sell require output ≥ TWAP-implied output × (10,000 − slippageBps) / 10,000 in addition to existing quote and exact-balance checks. Thin liquidity can refuse a run; maxPerRun and slippageBps remain voted Strategy parameters. **IMMUTABLE** execution rule.
- Proven against the published Base Uniswap v3 deployment (router 0x2626664c2603336E57B271c5C0b26F421741e481, quoter 0x3d4e44Eb1374240CE5F1B871ab261CD16335B76a, factory 0x33128a8fC17869897dcE68Ed026d694621f6FDfD) on the real WETH/USDC 0.05% pool 0xd0b53D9277642d899DF5C87A3966A349A798F224, on an owned Anvil fork: scenario K, `evidence/phase5/uniswap-twap-fork.log`. A pool created in the same block is refused `WindowUnavailable(cardinality = 1, oldestObservationAge = 0)`.
- Sandwich result recorded there (phase 5 ruling 5, audit rows T-4 / T-5): a same-block spot print of +2,500 / −2,501 bps leaves `price()` at 2,501.163805 USDC per WETH and `value()` unchanged inside the attacker's own transaction; the DCA run during the print reverts `TwapBoundExceeded(639362047019863, 795629616909476)` and, after the back-run, fills 799,164,044,735,887 wei WETH for 2 USDC (0.058% under the TWAP-implied amount, voted tolerance 0.50%); a 25% stop-loss does not fire on a −25% print; the deadline unwind during that print reverts and then sells for 4.994702 USDC (bound 4.972409). **IMMUTABLE** consequence of the two rules above.
- Fork rehearsal harness (test-only, not deployed): `src/baseFork.ts` pins Base block 51,000,000 (`BASE_FORK_BLOCK`; `FORK_BLOCK` overrides, `latest` opts out) so a rerun replays the same pool state and reuses anvil's on-disk RPC cache, and `warmUniswapPool()` pre-reads the ticks / tickBitmap / observations slots a 25% print crosses (1,547 slots) because a fork fetches cold storage from upstream one slot at a time.

## Relay and beacon (phase 5 rulings 6, 7, 9; not DAO rules, but hard to reverse for agents that depend on them)
- Treasury effect of a proposal (`relay/chain.ts`, shown in `/me`, `/proposals.json`, `/state.json` and the beacon): `usdcOut` counts `USDC.transfer` and `USDC.transferFrom` out of the Safe; `usdcApproved` counts `approve` / `increaseAllowance` by the Safe; `usdcAtRisk` is their sum. An inner transaction with `operation != 0` is labelled `DELEGATECALL ...` and flagged. **PROCEDURAL** — closes ECO-06's "usdcOut 0" cases; the execution-level answer is MultiSendCallOnly above.
- The template-instance panel is bound to the decoded calls, never to the details JSON (A5-11): the candidates are the non-DAO addresses the voted multicall calls, and a details JSON naming an address no call touches produces a flag instead of a panel. **PROCEDURAL**.
- Config proposals are decoded and flagged (phase 5 ruling 10): voting + grace below the 3,600 s poll cadence (ECO-04), `quorumPercent > 100` (T-9b), `sponsorThreshold >= totalShares` (T-9c), a `votingPeriod` that overflows `uint32(block.timestamp) + votingPeriod` (GOV-07b), and either period 0 (`NotApplied`). Nothing is refused on chain — no on-chain cap on Config values was added (rejected in ruling 10) — the flags appear in `/me.warnings`. **PROCEDURAL**.
- `/me.shareLiability` and `state.treasury.shareLiability` = `WorkManager.activeRewardShares()`; `navUsdcPerShare` divides deposit NAV by shares + that liability, exactly as `DepositShaman` prices a deposit. **PROCEDURAL**.
- T0 pass entropy floor = 128 bits, estimated by `relay/pass.ts` (character model after collapsing repetition, and, for a pass that is a phrase, at most 12.9 bits per distinct word); every T0 path including `op=identity` refuses below it (phase 5 ruling 9, A5-08). A pass of 32 random bytes (base64url or hex) or 10+ random words passes. Dictionary words concatenated without separators past ~28 characters are not caught (no dictionary is shipped). **PROCEDURAL**.
- Rate limits count and persist before rejecting (A5-09), so the per-request `reload()` no longer discards them. The bucket key is still the `cf-connecting-ip` header: the relay must sit behind Cloudflare or answer only on loopback. **PROCEDURAL**.
- An intent is answered `ok` only from a receipt that exists on chain; a recorded row naming a transaction that is on no block is dropped and the intent is broadcast again (A5-10). `/pending.json` exposes the signed-transaction journal and every unfinished request. **PROCEDURAL**.

## Disclosures (phase 5 ruling 10: documented, not fixed; each one is a residual an agent must price in)
- **OPS-05** Circle can blacklist the Safe: every ragequit naming USDC, every deposit and every Payment then reverts until Circle undoes it, and the only exit left is `ragequit(tokens=[])`, which burns shares for nothing. No on-chain remedy exists; accepted as the user's choice of settlement asset (see the settlement-asset line above).
- **NAV-05 / ECO-08** Exit is pro-rata of the Safe only: while a Strategy or Project holds fraction f of NAV, an exiting member forfeits f of its value to the stayers, so exit is most expensive exactly when the DAO is doing something, and a large passed instance blunts exit as a remedy against the next proposal. Explicit phase 4 ruling, user-confirmed, "not softened".
- **NAV-02** Empty treasury with shares outstanding (everything paid out or held as a non-USDC asset) re-prices every share to 1 USDC: the next depositor gets 1 share per USDC and donates the rest to the old shares. The same rule that removes the pre-genesis trap (ruling 8) produces this mirror image; `quote()` shows it before the deposit.
- **NAV-06** A Ready-but-unprocessed proposal (expiration 0) can be executed at any later time, after deposits that had no vote on it. `/me` lists Ready proposals with their treasury effect; the deposit path does not refuse while one exists.
- **ECO-05** Proposal spam costs one share and gas: 20 self-sponsored proposals with a failing action must each be processed (in sponsorship order) before later ones execute. The 8,000,000 baalGas cap makes each of them processable by anyone; clearing them still costs gas per proposal.
- **ECO-09** The sponsor budget is a relay policy, not a DAO rule: three execute intents (0.00056 ETH reserved each) exhaust the Base daily cap of 0.002 ETH, after which every member falls back to self-paid transactions for the rest of the UTC day. T0 members have no self-paid path; that is part of what T0 trusts the operator with.
- **A5-13** `/proposals.json` and `/me` grow with the number of proposals; paging exists (`?open=1`, `?before=&limit=`) but `/me` embeds every open proposal unconditionally, so a spammer inflates the document every agent polls.
- **A5-14** The agent-facing snippets do not fetch or hash the constitution; only `beacon:validate` (an operator tool) checks the published bytes against the on-chain hash. An agent that trusts a mirrored constitution without hashing it is trusting the host.
- **A5-07** T0 custody: the relay's 32-byte secret plus a pass reproduces that account's key, so whoever holds the secret can sign any intent for every T0 account. That is what custodial-lite is; the README says so, and T1 (own key) is the primary path.
