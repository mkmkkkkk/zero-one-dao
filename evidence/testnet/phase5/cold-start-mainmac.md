## Findings

These are what a stranger with nothing but the URL actually runs into. Ranked by how likely each one is to
stop or mislead a real agent.

### 1. Nothing served tells an agent how to get the USDC that `deposit` requires. This stops a careful agent dead.

Line 10 reads `deposit op=5 amount=<USDC raw units>  pulls USDC from your address into the Safe, mints
shares at NAV`. A key that was generated thirty seconds ago holds none. The settlement token is the DAO's own
contract at `0x0dA8d8E3B63De048855D311431E8e1f7F3f7DD3a`, not Circle's Base Sepolia USDC, so there is no
public faucet for it, and no faucet is named in the 44 lines, in `llms.txt`, or in either snippet.

What actually happens is that the relay quietly faucets the depositing address first: my T1 deposit produced
an unasked `faucet` top-up of 25 USDC (`0xdc2ee2df…`) before the deposit itself, and the T0 deposit did the
same for 20 USDC. It works — but only if the agent sends a deposit it has every reason to believe will
revert. An agent that checks its balance first, which is exactly what a careful one does, concludes it cannot
join and goes looking for a faucet that does not exist.

One clause on line 10 fixes it, e.g. `on this testnet the relay tops your address up first`.

### 2. `/me/<address>.json` reports `custody: "self-custody"` for a T0 account. The relay holds that key.

Line 37 makes `/me/<address>.json` the document an agent reads about itself, and it is the only `/me` path the
README advertises. For my T0 address it says `"custody": "self-custody"` before the join, after the join, and
after the exit — see the T0 table above and `cold-start-mainmac-T0.log`. Both `/relay` responses and the
unadvertised `/me/pass/<hash>.json` correctly say `"custody": "custodial-lite"`.

This is the one field that tells an agent whether somebody else can sign for it, and the advertised document
gets it backwards. It also silently contradicts line 41 — *the relay's secret is every T0 key* — which is the
DAO's central trust disclosure. An agent that trusts `/me` over the prose will believe its funds are safer
than they are. This is a defect in the served state, not a documentation nit.

### 3. Proposal 1 is executable right now by any stranger, and executing it breaks a promise the README makes.

Line 15 says `execute op=3 proposalId=<id> data=<proposalData>   anyone, after grace`. Proposal 1 is a Config
proposal setting votingPeriod and gracePeriod to 120 s each; it passed 50 / 0 and its grace ended at
2026-09-11T07:14:24Z. So a stranger who reads line 15 and notices a `Ready` proposal will execute it, as the
README invites — and the relay's own warning in `/me` says the resulting 240 s total is below the hourly poll
cadence line 39 promises, so a member polling hourly can miss the next proposal entirely, vote and exit
included (ECO-04). The served instructions currently point a new agent straight at the one action that
degrades the DAO's safety property for everyone.

I did not execute it. It is a test-only proposal waiting on the operator, but nothing served says so to an
agent, and the DAO has no mechanism that stops one.

### 4. The T0 line hides that a partial exit is possible, which is a money decision made on missing information.

Line 36 lists `op=ragequit` with no parameters, alongside ops that do carry parameters (`op=deposit&amount=`,
`op=vote&proposalId=&approve=yes`). Read on its own it means T0 exits are all or nothing. They are not:
`op=ragequit&amount=8000000000000000000` burned exactly 8 of my 20 shares
(`0xe3627e08…`, verified on chain). A T0 agent that wants to take half its money off the table will instead
exit completely and lose its membership, because the served text never mentioned the parameter.

### 5. `amount` is ambiguous between the T1 example and the T0 query string, and getting it wrong costs a transaction.

Line 10 defines `amount` as USDC raw units. Line 30's T1 example is `deposit --usdc 100`, a whole-USDC flag.
Line 35's T0 form is `op=deposit&amount=`, with no unit. An agent that pattern-matches the visible `100` onto
the T0 query string sends `amount=100` and deposits 0.0001 USDC — a mined, irreversible, pointless
transaction with a dust share position attached. I used raw units by cross-reading line 10, which is correct
but required holding two lines apart in mind. Writing `amount=<USDC raw units, 6 decimals>` on line 35 removes it.

### 6. Smaller things that cost time but did not stop me.

- The README never says the snippet generates the key file if it is missing. Line 29 shows
  `node snippet.js join --key agent.key` and line 33 says only *keep the key file 0600*, so an agent
  reasonably goes off to generate one first. Running the command is in fact enough.
- `/relay` responses point at `/me/pass/<hash>.json`, a path the README's endpoint inventory on lines 37–38
  never names. It works and it is the correct view for a T0 account (it is the one that reports
  `custodial-lite`), but an agent that only trusts advertised paths will not use it.
- Line 37 promises *my votes* in `/me`. There is no top-level field by that name; the information is
  `myVote` inside each entry of `openProposals`. Correct, just not where the wording points.
- `--summary` is what makes the propose quote's `details` carry the paramsHash and codeHash the snippet
  verifies, but it does not appear in the propose example on line 31. It defaults to empty and the run
  still passes, so this is cosmetic.

### 7. What worked exactly as advertised, and is worth keeping.

The 44 lines were enough to go from a URL to a voted proposal and a partial exit on both paths, twice, with
no other input. `ok` never arrived before the hash was on chain, exactly as line 41 promises: all 14
transactions read back `status=0x1` from an independent RPC. The propose quote let the snippet re-derive the
instance address and re-encode the Payment params before signing, so the relay could not have swapped the
code. The same-block vote rule on line 40 needed no handling — the relay reported `waitedBlocks: 0` and the
vote landed. And `/me` carried a live economic warning about proposal 1 that I had not asked for, which is
how finding 3 became visible at all.
